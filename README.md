# Bitcoin DeFi Bench

Bitcoin DeFi Bench is an evaluation suite that measures how well an agent optimizes capital on Bitcoin-native payment and settlement rails. Each task family is a deterministic, seeded simulator that poses a legitimate operator's problem (where to place directional channel capital, which settlement object to use, how to size an Ark server's Lightning capacity, how to bond a service) behind one interface, `act(observation: JSON) → action: JSON`, with a per-episode budget, a scoring function, and named baselines that run in the same harness, in the same process, on the same seeds as the agent. A task's score is a normalized gain, (agent − random) / (oracle − random), clipped to [−1, 1.5] and reported with a cluster-robust interval over seeds and a preregistered practical-equivalence band; the output is a profile across families. The bench is built on "Where the Capital Bound Moves: Settlement Objects, Proof-Carrying Registries, and a Warden Model for Agent Payment Networks" (Dugan, Spiral program, September 30, 2026), at `paper/where_the_capital_bound_moves.md` in <https://github.com/patrickdugan/Spiral>, and imports that paper's reference model unmodified from a checkout pinned at commit `9824c30ad402cc9bca768eca27d176e0e8788db5`.

Family 10 scores the DLC as its specification defines it: how coarsely to round a numeric contract's payout curve, which sets how many adaptor signatures both parties must make, and how much collateral to lock, which sets how much of the curve it can pay. Its rules and test vectors come from dlcspecs, pinned by commit.

Family 9 scores the coordination layer those rails depend on: holding the key that signs for the capital, posting where counterparties read, sending private messages only they can open, buying a service from one over Nostr, and delivering over the bitchat Bluetooth mesh when the internet is down. Its unit is still sats, and its rules come from the NIPs and the bitchat whitepaper, pinned by commit.

It is not a red-team benchmark: it contains no coalition, covert-channel, or Sybil tasks, and where family 9 poses hostile requests the agent under test is only ever the defender. It is not a measurement of Lightning, Ark, BitVM, Nostr, or bitchat: nothing contacts a live network, mainnet, signet, relay, or radio, hidden balances and demand are synthetic, and every protocol parameter is a cited input rather than a constant. It does not produce a composite score. Its routing and placement baselines are calibrated against the effects the Spiral campaigns measured, so an agent result far outside those effects is treated as a suspected harness defect and audited before it is reported, and any result not covered by `prereg/v0.md` is reported as exploratory.

- Status: the harness and family 1 (directional placement) are implemented, preregistered, and run on 32 confirmatory seeds with baselines. Family 3 (settlement-object selection) is implemented on the pinned model with a server-tier term the bench supplies, preregistered by amendment, and run on the same 32 seeds with baselines; three of the choices the design calls for are not offered yet (docs/tasks.md §0.1, §4.6). One LLM, Bonsai 8B with thinking off, has been run on family 1, bare and (on development seeds only) with a failed-pairs skill, and on family 6 bare and with a min-cost-flow skill on the confirmatory seeds; docs/saturation.md has what it reaches and where it fails. Family 6 (position netting toward a target settlement value) is implemented, preregistered by amendment, and run on the same seeds with baselines. Families 2, 4, 5, 7, and 8 are specified only, against the scorecard in docs/tasks.md §0.2; family 7 has its first proof-cost grid measured (§8.5). Family 9 (Nostr coordination under a protected key, and the bitchat mesh; seven cells) was added to the scorecard on 2026-10-08 and is specified. Its protocol core is built and passes the BIP-340, NIP-44, NIP-19, and NIP-59 vectors; its cells are not built yet (docs/tasks.md §10.9). Family 10 (designing a numeric DLC, three cells) was added on 2026-10-08, is built, reproduces the DLC specification's test vectors, and has been run on the development seeds with baselines; it is not preregistered yet (docs/tasks.md §13.9).
