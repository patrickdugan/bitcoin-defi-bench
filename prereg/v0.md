# Preregistration v0

Drafted 2026-10-01, before any bench code existed. Status: **frozen for family 1 on 2026-10-01**. The family 3 sections (5.2, 6.2) remain draft.

Frozen families: placement

This document covers two things: the baseline run that produces the first results table (families 1 and 3, 32 seeds each), and the rules any later agent run is reported under. Task definitions are in `docs/tasks.md`, cited below as "tasks §n". A bare §n refers to this document.

## 1. Freeze

The preregistration freezes when it is committed with the status line changed to "frozen". From then on the harness writes the SHA-256 of this file into every run record and prints it in the table header. No task in a family is run on confirmatory seeds before that family's sections are frozen.

The harness reads the "Frozen families" line above and refuses to run a confirmatory block for a family that is not on it. Sections 5.2 and 6.2 (family 3) cannot freeze until the pin gap in tasks §0.1 is resolved. Sections 5.1 and 6.1 (family 1) froze once the topology source in tasks §2.6 was chosen: samples of the July 2023 public-gossip snapshot.

Amendments are appended under §11 with a date and a reason and never edit earlier text. An amendment made after a family's confirmatory seeds have been run moves that family to a fresh seed block.

## 4. Estimands and estimators

As in tasks §1.6, restated here so that they are frozen.

- **Native value.** Family 1: success rate over the 110 evaluation demands, in percentage points. Family 3: −ln 𝒟, with an infeasible choice scored at twice the largest feasible grid 𝒟 for that episode.
- **Paired difference.** Mean over seed clusters of the within-seed mean difference between two policies, with a two-sided Student-t interval on 31 degrees of freedom. The unadjusted 95% critical value is 2.040.
- **Normalized gain.** G = Σ_s (A_s − R_s) / Σ_s (O_s − R_s), clipped to [−1, 1.5], with a delete-one-cluster jackknife interval on the same critical value.
- **Headroom guard.** If the unadjusted 95% interval for oracle − random does not exclude zero, G is not reported for that task.

The harness computes the critical values from the t distribution. The numbers quoted here are for the reader.

## 5. Equivalence bands

| Family | Band, native units | Origin |
|---|---|---|
| 1 (and 2) | ±1.0 success point | the earlier Spiral preregistrations |
| 3 | ±0.05 in ln 𝒟 | chosen here |

A difference is **equivalent** when its whole interval lies inside the band, **positive** or **negative** when its whole interval lies on one side of zero, and **inconclusive** otherwise. Equivalent and positive can both hold and are then both stated, as the earlier campaigns did for the +0.35 learning effect.

## 6. Hypotheses

### 6.1 Family 1

- **H1 (stationary).** `failure_aware` − `random` is positive on `placement/stationary`.
- **H2 (shift).** `failure_aware` − `random` on `placement/shift` is not positive beyond the band: its interval is not wholly above +1.0. The falsifying outcome is an interval wholly above +1.0 or wholly below −1.0. The first would mean the heuristic anticipates a hotspot it has never observed, and would be investigated as a leak in the shift generator before anything else.

Prediction for the normalized gains, descriptive and not tested: `failure_aware` near 0.7 to 0.8 on stationary and near 0 on shift. These come from the recorded success rates (random 0.875, failure-aware 0.929 under stationary demand) and a rough ceiling of 0.94 to 0.95 if every hotspot demand were delivered.

### 6.2 Family 3 (not frozen)

- **H3.** On `settlement_object/many_bursty_long`, `always_vtxo` − `always_channel` is positive in −ln 𝒟; that is, 𝒟_C / 𝒟_V exceeds one.
- **H4.** On `settlement_object/few_steady_recycling`, `always_channel` − `always_vtxo` is positive; that is, 𝒟_C / 𝒟_V is below one.

These are the paper's §7 item 2 falsifier: the paper's §3.3 claim fails if the ratio does not exceed one in the first corner or does not fall below one in the second. Under the pinned definitions the direction is already known from the vendored test (§2 above), so H3 and H4 would be a replication on new seeds with a common volume denominator, not a blind prediction. With a server-tier term charged, the direction is not known to me, and the hypotheses would be restated against that definition before freezing.

### 6.3 Secondary, declared and descriptive

Reported with unadjusted intervals and labelled secondary: the `none` row; `random` − `none`; delivered-volume share; breakdowns by balance model and by sampling mode; the cells `many_bursty_correlated` and `many_bursty_boarding`; every normalized gain.

## 7. Multiplicity

The primary family is H1 through H4. Intervals for primary contrasts are Bonferroni-adjusted for four comparisons: critical value 2.652 on 31 degrees of freedom, for family-wise 95% coverage. If family 3 is not frozen when family 1 runs, the primary family is H1 and H2 and the critical value is 2.356. The table prints both the unadjusted and the adjusted interval for every primary contrast and says which is which.

Calibration gates use unadjusted intervals. They are checks on the harness, and a looser gate is the conservative direction for a check whose failure blocks reporting.

For agent runs, the primary family is one contrast per implemented task, agent − the task's reference baseline (the heuristic in families 1 and 3, the retry wallet in family 2), Bonferroni-adjusted over the number of tasks reported.

## 8. Stopping

The seed count is fixed at 32 per family. There is no interim look and no optional stopping. The confirmatory run is one invocation; if it fails partway for an infrastructure reason it is rerun whole, and the failure is noted in the run record. Episodes are deterministic, so a rerun cannot change a value. Each agent run is likewise one invocation, and it runs the baselines again in the same process on the same seeds.

Any extension uses the next reserve block, is declared in an amendment before it runs, and is reported both separately and combined with the original, as the Spiral replication and precision campaigns were.

An agent whose output is not deterministic is run once per episode. Reruns are permitted only for infrastructure failure and are logged. There is no best-of-k.

## 9. Agent runs: what is flagged before it is reported

The flags of tasks §1.8 apply. The one with a predeclared expectation is family 2:

- **Expectation.** A good agent is practically equivalent to the retry wallet at the three-attempt budget. The measured increments beyond retries were +0.35 points for terminal-feedback learning and a further +1.11 for an exact hidden-state oracle that inspects the whole catalog.
- **Rule.** An agent − retry-wallet interval that is not inside ±1.0 point, in either direction, is not reported as a result. It is listed as flagged, and the audit checks, in order: the identity controls (`prefix_oracle_3` equals `retry_wallet`; a scripted replay equals the built-in baseline), whether the observation leaks hidden state, whether attempts were charged, and whether candidate order is canonical. Only after those pass is the number reported, with the audit note.

A normalized gain above 1 on any task, and a gain beyond the band on `placement/shift`, are handled the same way.

### 9.1 LLM agents

- **Identity.** The agent identifier in the run record binds the model file's SHA-256, the runtime build, the sampling parameters, and the SHA-256 of the adapter's prompt text.
- **Development.** The prompt and the adapter are developed on development seeds only and are fixed, with the prompt hash recorded, before the confirmatory run.
- **One run.** One confirmatory invocation per agent identifier. A rerun is permitted only for infrastructure failure and is logged.
- **No rescue.** Output that does not parse as an action is passed to the harness as it is, is rejected as malformed, and costs an attempt. The adapter does not retry, repair, or substitute a default.
- **Regime blindness.** The request seed is derived from the episode seed, the cell, and the turn, and not from the task, so a deterministic server returns the same decision under both regimes.
- **Contrasts.** The primary contrasts are agent − `failure_aware` on each placement task, two-sided, Bonferroni-adjusted over the two tasks. No directional prediction is registered for any particular model.

## 10. What is exploratory

Anything not named in §5 through §9: any task, cell, contrast, subgroup, or metric added after freezing; any analysis chosen after seeing a table; any run on development seeds. Exploratory results are reported in a separately headed section of the table and are never mixed into the profile.
